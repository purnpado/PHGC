# 진학 상담 대시보드 및 지원 현황 기능 개선 기획안

## 1. 개요
고입 시스템의 이중 지원 금지 규정(마이스터고 1개교, 특성화고 취업/일반 전형별 제한, 일반고 지원 제한)을 프론트엔드 검증 로직에 반영하고, 대시보드의 복잡한 UI를 정돈합니다. 또한 잘못 입력된 지원 현황을 삭제할 수 있는 기능을 추가하여 통계 화면의 가독성을 향상시킵니다.

## 2. 세부 개선 사항

### 2.1 고입 시스템 이중지원 금지 규정 반영 (유효성 검증)
- **마이스터고**: 단 1개의 학교에만 지원 가능. (동일 학교 내 특별/일반 전형 복수 지원은 허용됨)
- **특성화고**:
  - 취업희망자 전형은 단 1개 학교만 지원 가능.
  - 일반전형은 단 1개 학교만 지원 가능하며, 취업희망자 전형에 지원한 경우 불합격이 확정된 이후에만 일반전형 지원이 가능함.
- **일반계고**: 마이스터고, 특성화고, 자사고, 외고 등에 지원하지 않았거나 모두 불합격(또는 포기) 처리된 학생만 지원 가능.

### 2.2 진학 상담 대시보드 UI 정리
- 중단에 위치했던 버튼들(우리 반 전체 매트릭스 보기, 우리 반 지원희망, 우리 학교 지원현황, 원서접수대장)을 디자인 시스템에 맞추어 그룹화하거나 레이아웃을 간소화합니다.
- 테이블 내 우측 끝에 있던 `📝 지원 현황`과 `🎯 고교별 진학상담` 버튼을 조화롭게 배치하여 각 행의 가독성을 높입니다.

### 2.3 우리반 지원희망 통계 테이블 가독성 개선
- 한 학생이 1개 학교 내에서 여러 지망(1지망, 2지망 등)을 쓰거나 다른 전형을 쓸 경우 발생하는 중복 행을 시각적으로 묶습니다.
- HTML 테이블의 `rowspan` 속성을 사용하여, 동일한 입학년도/구분/학교명인 경우 학교 이름 셀을 병합하여 한눈에 파악하기 쉽도록 렌더링 로직을 개선합니다.

### 2.4 학생별 지원현황 삭제/초기화 기능 추가
- (Backend) `db.go`에 `DeleteStudentApplication` 함수를 구현하고 `app.go`에서 API로 노출합니다.
- (Frontend) 학생 지원 현황 편집 모달 내부에 `[🗑️ 기록 삭제]` 버튼을 추가합니다.
- 이 기능을 통해 실수로 여러 학교를 입력해 통계에 잘못 잡히는 문제를 현장에서 즉각 대처할 수 있도록 합니다.
