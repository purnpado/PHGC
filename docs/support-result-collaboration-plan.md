# 지원·결과 관리 및 오프라인 협업 기획안

> 상태: 구현 기준 확정 전 / 범위: PHGC 학교 로컬 기능, 교내 파일 취합, 최소 중앙 집계
>
> 이 문서는 비공개 소스 저장소에서만 관리한다. 프로그램 릴리즈·교사용 배포본·`data` 폴더에는 포함하지 않는다.

## 1. 목적

학교는 올해 학생별 실제 지원·합격 결과를 누적하고, 입시 종료 뒤 합격자 점수로 고교·학과·전형별 최고점·평균점·최저점을 산출한다. 담임 입력은 암호화 파일로 학년부장에게 취합하며, 중앙 서버에는 개인정보 없이 확정 커트라인 집계만 제출한다.

## 2. 역할

| 역할 | 권한 |
| --- | --- |
| 학년부장 | 전체 수정, 담임 파일 병합, 교사용 배포 파일 생성, 계정 재설정, 마감·잠금, 중앙 커트라인 제출 |
| 담임 | 자기 반의 지원·결과 및 허용된 비교과 입력, 자기 반 변경분 내보내기 |
| 진로부장 | 전체 학생·전체 현황 조회만 가능. 수정·병합·배포·제출 불가 |

## 3. 학생별 지원 이력

지원 기록은 `학생 × 전형 × 고교` 단위이며, 특성화고·마이스터고는 학과 지망을 하위 항목으로 둔다. 학과 지망을 별도 지원으로 세지 않아 학교 전체 지원자 수가 중복되지 않게 한다.

- 상태: `미입력 / 지원 예정 / 지원 완료 / 합격 / 불합격 / 포기 / 최종 진학`
- 지원 당시의 학교별 산출 점수와 점수 기준을 스냅샷으로 보존한다.
- 학과 지망은 학교 공식 학과 수만큼 최대 5지망까지 제공한다. 동일 학과 중복 선택은 차단한다.
- 결과에는 최종 배정 학과를 별도 기록한다.

### 전형별 기록 기준

| 구분 | 기록 | 점수·중앙 집계 |
| --- | --- | --- |
| 마이스터고 | 고교·학과·일반/특별전형·지망·결과 | 점수 저장 및 최종 커트라인 집계 포함 |
| 특성화고 | 고교·학과·일반/취업희망전형·지망·결과 | 점수 저장 및 최종 커트라인 집계 포함 |
| 자사고·울산외고 | 학교·결과 | 점수 집계 제외. 불합격 시 후기 일반계고 지원 가능 |
| 후기 일반계고 | 학교·학과 없이 일반계고 점수·결과 | 학교 내부 분석만 |
| 기타 | 타 시도, 울산애니원고 등 학교·결과 | 점수·중앙 집계 제외 |

과학고는 해당 시점에 전형이 끝났으면 관리 대상에서 제외한다. 자사고·울산외고 지원자는 마이스터고·특성화고와 병행하지 않으며, 합격하면 이후 전형을 `미지원(선행 전형 합격)`으로 표시한다.

## 4. 화면

1. 진학상담 대시보드에 `지원·결과` 열을 추가한다.
2. 학생별 상담 화면에 `지원·결과` 탭을 추가한다.
3. 별도 `사전 지원희망 현황` 및 `우리 학교 지원·결과 현황` 화면을 제공한다.

사전 현황은 실제 원서접수와 구분해 반드시 `예상치`로 표시한다. 학교 전체 예상 지원 인원과 학과별 1~5지망 인원을 분리한다. 실제 현황에서는 지원 완료·합격·불합격·최종 진학, 결과 미입력, 학급별 진행률을 제공한다.

## 5. 고교 공식·학교·중앙 자료의 상담 활용

상담 화면은 자료 출처를 섞지 않고 다음 순서로 표시한다.

1. **고교 공식·교육청 자료**: 운영자가 공식 발표 문서가 있을 때만 등록한다. 모집학과, 전형요강, 공식 공개 성적이 대상이다. 출처·갱신일을 표시하며 학교 PHGC에서는 읽기 전용이다.
2. **우리 학교 자료**: 학년부장이 합격자 최저점·최고 불합격점을 입력한다. 평균점은 수기 입력하지 않고, PHGC에 누적된 실제 합격자 지원 점수 스냅샷으로 자동 계산한다. 합격자 기록이 없으면 평균은 비워 둔다.
3. **중앙 서버 자료**: 참여 중학교의 개인정보 없는 확정 커트라인 집계다. 우리 학교 자료가 부족할 때 보조 참고자료로만 사용한다.

공식 자료는 자동 수집하지 않는다. EduBridge 운영자가 확인 후 수동 등록하고, PHGC는 공통 데이터 동기화·업데이트로 읽기 전용 사본을 반영한다.

## 6. 배포·계정·취합

학년부장은 학교명·학급 수·입학년도·관리자 비밀번호·공용데이터 비밀번호를 설정하고 `301` 등 담임 계정과 `jinro` 계정의 초기 비밀번호를 부여한다.

향후 교사용 배포 파일(`.phgcpkg`)은 대상 교사의 범위만 포함한다.

- 담임용: 해당 반 암호화 DB, 암호화 설정·커트라인, 공용 키 정보, 계정 검증 정보, 배포본 버전
- 진로부장용: 전체 조회 자료
- 제외: 관리자 개인 키, 관리자·공용 비밀번호 평문, 다른 반 DB

교사는 배포 파일을 가져온 뒤 최초 한 번 공용데이터 비밀번호와 초기 비밀번호를 입력하고, 이후 개인 비밀번호로 변경한다. 현재 구현된 `.phgcreset` 파일은 담임 비밀번호 재설정에 사용하며, 장기적으로 배포 파일 체계에 통합한다.

담임은 자기 반의 비교과·지원결과 변경분만 `.phgcpatch`로 내보낸다. 학년부장은 기준 배포본 버전, 학급, 작성자, 중복 여부를 검증하고 병합한다. 동일 학생·항목의 충돌은 자동 덮어쓰지 않고 학년부장이 선택한다.

## 7. 중앙 전송 원칙

### 중앙에 전송하지 않는 것

학생 이름, 학급, 개인 점수, 개인 지원 이력, 성적 원본, 출결·봉사·행발·창체 원본을 전송하거나 저장하지 않는다. 자동 전송·자동 수집도 하지 않는다.

### 입시 종료 후 커트라인 제출

학년부장이 확정·검토 후 수동 제출한다.

```text
입학년도 × 중학교명 × 고교 × 학과(또는 학교 전체) × 전형 × 점수 기준
→ 합격자 최고점 / 평균점 / 최저점
```

### 원서 접수 전 예상 지원현황

중앙 전송은 향후 선택 기능으로만 검토한다. 구현 시 이름은 `참여 중학교 기준 울산권 예상 지원현황`으로 한다. 제출 학교만 조회 가능하며, 중앙에는 고교·학과·전형별 1~5지망 집계와 학교 전체 예상 지원 인원만 보낸다. 다른 중학교별 원자료는 공개하지 않고, 1~2명 값은 `3명 미만`으로 숨긴다. 원서접수 종료 뒤 예상 자료는 비공개 또는 삭제한다.

## 8. 구현 순서

1. 학급 DB의 지원 이력·학과 지망 데이터 모델 및 역할별 API
2. 학생별 지원·결과 입력과 학교 내부 현황 화면
3. 담임 변경분 파일의 지원·결과 확장과 학년부장 병합
4. 교사용 배포 파일(`.phgcpkg`) 생성·가져오기
5. 합격자 기반 커트라인 자동 평균·최고·최저 산출
6. 운영센터의 공식 고교·교육청 자료 읽기 전용 배포
7. 선택 기능: 참여 학교 기준 울산권 예상 지원현황

각 단계는 AES-256-GCM 암호화, 기기 비종속, 최소 개인정보 원칙 및 기존 데이터 호환성을 유지해야 한다.
